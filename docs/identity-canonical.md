# Canonical identity

The public identity entry points are `https://inflite.ai/auth/` and `https://inflite.ai/account/`. Each retains its role-specific API at `<prefix>/api/account/*`, static modules, icons, and a scoped manifest. Root `today/src/identity.js` exposes `isIdentityPath(path)` and `identity(request, env)`; route `/auth`, `/auth/*`, `/account`, and `/account/*` through the Worker before static assets.

Transport stays at the fixed `auth.inflite.ai` and `account.inflite.ai` service hosts. The public Worker constructs headers from an allowlist, forwards only account/known-device cookies, and authenticates using HUB_KEY. Middleware validates that key before `_identity.js` accepts Apex Origin for identity mutations. Browser Origin and WebAuthn clientDataJSON remain untouched. New passkeys already use the `inflite.ai` RP; legacy credentials keep their stored RP and the existing Related Origin Requests grant. No credential or session migration occurs.

Ordinary legacy human documents at `/`, `/index.html`, or `/go` redirect to the canonical entry. Legacy API/static/OAuth callback transport stays available. Account email links and QR links now point to the canonical page. Browser-return URLs are restricted to exact app paths; the explicit Mail fallback `/mail/standalone/` is preserved without admitting arbitrary nested paths. No opaque OAuth/code/token parameters are rewritten or replayed.

Both prefixes require the authenticated service binding/HUB_KEY, including documents. Missing configuration fails closed with a temporary-unavailable response. Identity responses and APIs remain private/no-store as before; manifests keep each prefix as their scope. Existing sessions are carried by the same HttpOnly, Secure, SameSite=Lax cookie for `inflite.ai`.

Validation: Root `tests/identity-api.test.cjs` covers transport, cookie isolation, exact origins, reviewed redirects and no write replay. Apps `.tools/tests/unit/identity.test.mjs` runs the real Root proxy through Apps middleware, API and SQLite for signup, sign-in, shared sessions, logout, role separation, passkey origin/challenge checks, prefixed asset graph and native compatibility. `.tools/tests/identity-ui.test.cjs` runs the actual canonical sign-in/account UI at phone and desktop widths against that backend; no account API stubs or credential shortcuts are used. Existing sign-in handback/account-mail suites also pass.
